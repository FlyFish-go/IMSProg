IMSProg Windows x64 portable package
====================================

1. Extract the whole ZIP to a writable folder. Keep every DLL and subfolder
   beside IMSProg.exe; do not copy DLLs into System32.
2. Run IMSProg.exe. The executable and DLLs are unsigned, so Windows may show
   a SmartScreen warning.
3. Select CH341A/B, CH347T or CH347F (and an SPI clock) in the Programmer menu.
4. If connection fails, use Programmer > Programmer connection diagnostics.
   The diagnostics inspect USB metadata without sending flash commands.

USB and driver notes
--------------------

The driver\ folder contains the official, Microsoft-signed WCH driver package
(ch341wdm.inf 2.6.2025.4) for the SPI/I2C interface of CH341A/B, CH347T and
CH347F, including the WCH CH341/CH347 DLLs. Install it from
Programmer > Driver... or by clicking the driver item in the status bar
(administrator permission is requested). The status bar shows whether the
driver is installed. CH347 serial (COM) port drivers are not changed.

A device bound to WinUSB/libusbK keeps working through the bundled libusb.

Validation boundary
-------------------

CI builds this package as Windows x64 and performs hardware-free protocol,
backend, source-conformance, sanitizer, and startup smoke checks. Those checks
do not establish physical programmer compatibility, driver compatibility on a
particular PC, electrical safety, chip correctness, or throughput.

The complete dependency tree of every packaged EXE and DLL (including Qt
plugins) is checked after ZIP extraction. Startup checks run all three apps with
an isolated DLL search PATH and require an actual Qt window using the bundled
Windows platform plugin. The internal --portable-smoke-test argument uses Qt
test storage and disables the programmer's initial probe and automatic probe timer.

See WINDOWS_CH347.md for build, backend, connection, and safety details.
Third-party notices and the modified libusb corresponding source are included
under LICENSES and SOURCE.

Chip database tools
-------------------
IMSProg_database_update.exe downloads the upstream chip database. Open it from
File > Update chip database, or run it directly. Close the editor before updating;
restart IMSProg after a successful update. The updater writes the shared user
IMSProg.Dat under the Windows application-data directory; the main program gives
that file priority over the database supplied beside IMSProg.exe.

IMSProg_editor.exe edits chip records manually. File > Edit chips Database opens
it. To edit an online-updated database, open the shared user IMSProg.Dat, then
save back to the same location. Updating again replaces those custom records.
Online updates require Internet access and use the original project's HTTPS
endpoint; the package includes the Qt Network and Windows TLS runtime.
